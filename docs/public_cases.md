# Complaint-backed public cases

## What these cases are

Six small MJCF pairs, each built around one mechanism that a real person publicly complained about,
and each run end to end through the accepted Metrifid product journey.

Every one of them is a **mechanism analogue**. The models were written from scratch for this
repository to exercise the same compiled mechanism the complaint describes. They are not copies of
the upstream assets, they do not execute Newton, USD, Isaac, or Robosuite code, and they do not
reproduce any upstream import, export, or simulation behavior. When a case is derived from a public
issue, the issue is the origin of the *mechanism*, not the source of the *files*.

Each case answers the release question directly: the model changed — what can I actually approve?

```text
1. Certify           do the compiled artifacts differ at all?
2. Model Review      what changed, and is any of it declared by a policy?
3. Declared review   with those exact changes declared, does the release pass?
```

The declared policy in each case is generated mechanically from the discovery receipt, to
demonstrate the two-pass workflow. **It is not release authority.** A human maintainer must inspect
and justify every declared rule before approving a real model change.

## Run all six cases

The gallery runs against an installed Metrifid distribution, not a source-tree import, and publishes
into a directory that must not already exist.

```bash
python examples/public_cases/run_all.py --output /absolute/absent/output
```

It writes one `case_result.json` per case, a `gallery_result.json` holding the stable projection, a
human-readable `gallery_summary.md`, and a `CHECKSUMS.sha256` manifest covering every published file.

Each case directory under [`examples/public_cases/`](../examples/public_cases/) carries its own
`case_manifest.json`, an `ORIGIN.md` naming the exact mechanism source, and `baseline/` and
`candidate/` model roots.

## Collision filtering

Three cases, all from the same family of complaints: a model round-trip silently changed which geom
pairs can collide.

- [`collision_filtering/mask_flattening`](../examples/public_cases/collision_filtering/mask_flattening/) —
  the `contype`/`conaffinity` bitmasks are flattened, so the set of eligible collision pairs changes
  even though every geom is still present. Origin:
  [newton#3235](https://github.com/newton-physics/newton/issues/3235) and
  [newton#3713](https://github.com/newton-physics/newton/issues/3713).
- [`collision_filtering/explicit_pair_loss`](../examples/public_cases/collision_filtering/explicit_pair_loss/) —
  an explicit `<contact><pair>` element is lost, so a pair that was deliberately enabled is gone.
  Origin: [newton#3713](https://github.com/newton-physics/newton/issues/3713).
- [`collision_filtering/exclusion_loss`](../examples/public_cases/collision_filtering/exclusion_loss/) —
  a `<contact><exclude>` element is lost, so a pair that was deliberately disabled starts colliding.
  Origin: [newton#3713](https://github.com/newton-physics/newton/issues/3713).

The independent control for the first case computes pair eligibility directly from the authored
bitmasks and confirms the eligible-pair set differs. The two loss cases confirm directly that the
element is present in the baseline and absent in the candidate.

The two loss cases are deletions, and deleting a compiled element shifts MuJoCo's compiled name
identity mapping. Metrifid treats that as a fail-closed condition: it publishes an opaque
complete-MJB residual that no policy rule can clear, so the declared review reports
`REVIEW_REQUIRED` rather than `WITHIN_DECLARED_POLICY`. That is the product declining to call a
change "within declared policy" when object identity itself moved, and it is worth understanding
before you write a policy that assumes deletions can be pre-approved.

## Mesh inertia

[`mesh_inertia/mode_change`](../examples/public_cases/mesh_inertia/) — the same concave mesh is kept
byte-for-byte, and only the inertia computation mode changes. The compiled body mass and inertia
change with it. Origin: [newton#3753](https://github.com/newton-physics/newton/issues/3753).

The mesh is generated by [`build_mesh.py`](../examples/public_cases/mesh_inertia/build_mesh.py) so
its bytes are reproducible, and the case manifest pins the expected mesh digest. The independent
control compiles both models and compares the compiled mass properties directly.

## Actuator transmission

[`actuator_transmission/frame_change`](../examples/public_cases/actuator_transmission/) — an actuator
declared with `jointinparent` is changed to `joint`. The transmission frame changes, so the same
control input produces a different generalized force. Origin:
[newton#3743](https://github.com/newton-physics/newton/issues/3743).

The independent control sets one frozen ball-joint pose and one frozen control value, runs
`mj_forward`, and compares the actuator moment and generalized force in both roles.

## Sensor attachment

[`sensor_attachment/site_change`](../examples/public_cases/sensor_attachment/) — a force/torque
sensor is moved from one site to another, so the compiled sensor attaches to a different object.
Origin: [robosuite#808](https://github.com/ARISE-Initiative/robosuite/issues/808).

The independent control reads the compiled sensor object IDs and confirms the baseline sensor is
attached to the sensor frame while the candidate is attached to the grip frame.

## How to interpret the decisions

```text
certify   NOT_CERTIFIED_COMPILED_DIFFERS (40)   the compiled artifacts differ
review    REVIEW_REQUIRED (40)                  something changed that no policy declares
review    WITHIN_DECLARED_POLICY (0)            every observed change is declared
```

A completed exit 20, 30, or 40 can be a referee decision. Metrifid finished its work and is telling
you what it found; it is not reporting that it crashed or that your model is wrong.

The first review pass runs with an empty policy on purpose. That is the discovery pass: it enumerates
every compiled change so you can see the complete list before declaring anything. The second pass
runs with those exact changes declared and bound to the candidate artifact.

## Claim boundaries

- The six owned cases are independently authored mechanism analogues. They are not upstream
  reproductions and they do not execute Newton, USD, Isaac, or Robosuite code.
- Nothing here proves cross-backend equivalence, behavioral equivalence, physical correctness, or
  safety.
- Certify decides compiled artifact identity only. Model Review decides static policy coverage only.
  Neither steps a simulation.
- The generated declared policies demonstrate the two-pass mechanism. They are not maintainer
  judgment and confer no release authority.
- Referenced public issues are the origin of each mechanism, not the source of any file in this
  repository.
